## Default

Composes `DatePicker` with the [Calendar](/docs/components/calendar) component. The selected date is formatted into the trigger's children, and the controlled `open` state closes the popover on select.

For typed entry, a regular `Input` parses the text while an icon button opens the calendar. `DatePicker.Anchor` positions the popover against the whole input instead of the icon button.

## API Reference

Built on the [Popover](/docs/components/popover) component. `DatePicker` owns no date state — the calendar's `selected`/`onSelect` and the trigger's children remain with the consumer, so every `react-day-picker` mode works unchanged. For form submission, a hidden input can be rendered next to the trigger.

### DatePicker

Contains all the parts of a date picker. Props are the same as [Popover](/docs/components/popover#popover).

### DatePicker.Trigger

The input-style button that toggles the popover. Renders the children as the formatted value, or the `placeholder` when children are empty.

### DatePicker.Anchor

An optional element to position the `DatePicker.Content` against. Props are the same as [Popover.Anchor](/docs/components/popover#popoveranchor).

### DatePicker.Content

The popover panel that contains the calendar. It defaults to `align="start"`, hides the popover arrow, and removes the popover's default width limit. All other props are the same as [Popover.Content](/docs/components/popover#popovercontent).

## CSS variables

The trigger reuses Hummingbird's `form-control` classes, so it follows the same border, focus, and disabled styling as [Input](/docs/components/input). The `date-picker-trigger` class exposes these CSS variables, which can be overridden to modify its appearance. Read more about customizing with CSS variables [here](/docs/customize/component#using-css-variables).

```css
.date-picker-trigger {
  --date-picker-placeholder-color: var(--text-color-muted);
  --date-picker-icon-color: var(--text-color-muted);
  --date-picker-icon-size: --spacing(4);
}
```
